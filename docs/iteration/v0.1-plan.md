# Elemental Survivor V0.1 Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan. In this workspace, execute inline because no internal sub-agent was requested.

**Goal:** Deliver a locally playable 3–5 minute Canvas 2D prototype with movement, automatic combat, three enemy types, three weapons, XP and three-choice upgrades, one Fire + Wind reaction, readable feedback, pause, death, restart, automated tests, browser evidence, and no damage to any pre-existing project.

**Architecture:** Use a single HTML route and native JavaScript ES modules. Keep deterministic gameplay rules in pure modules under `src/core`, declarative tuning in `src/data`, and browser-only input/render/audio/loop work under `src/runtime`. The browser owns one animation loop; the model owns one replaceable run state. Node's built-in test runner covers pure logic, while Playwright covers the real browser journey.

**Tech Stack:** HTML, CSS, JavaScript ES modules, Canvas 2D, Web Audio, Node.js 24 built-in test runner, Playwright, a small Node static server.

**Constraints:** Work is local-only. Do not initialize Git, commit, push, create a pull request, deploy, or add persistence. Use procedural shapes and sounds for V0.1. Every gameplay behavior follows red-green-refactor: create one failing test, run it and confirm the expected failure, implement the minimum, then run the focused and full suites.

## Success checks

- `npm test` passes all unit and integration tests.
- `npm run test:e2e` passes the start → move → attack → kill → XP → level-up → select → pause/resume → death → restart journey.
- `npm run check` validates the data and imports without warnings.
- A real browser run remains playable for at least three minutes, with first kill by roughly 5 seconds and first upgrade between 30 and 45 seconds under ordinary play.
- Restart replaces all enemies, projectiles, particles, timers, buffs, pending upgrades, and run statistics; the page still owns exactly one animation loop.
- Screenshot and local telemetry evidence are saved under `artifacts/v0.1/` and summarized in `docs/iteration/v0.1-playtest.md`.
- Expansion stops after the playtest; the next action is external expert review.
