## ACCEPT

- V0.5 继续保持“一局一个反应槽”，不扩充第二槽位、元素、反应、Boss、地图或 Meta。
- 第一次升级明确披露：本局只能激活一种反应，首个完成的元素反应锁定路线。
- Wind/Ice 卡显示对应反应配方；随机第三项显示“即时强化 · 不锁定反应路线”。
- 结算页展示中性的本局路线、反应激活次数和反应命中数。
- 删除会引导玩家选择另一条路线的结算文案，保护“是否自发重开”的测量有效性。
- 补同一步多伤害下的致死反应精确一次测试、50 次 GameLoop 生命周期压力测试、正式 URL 无测试 API 的 E2E 断言。
- 冻结现有反应、基础武器、玩家、敌人、生成和 Director 数值。

## MODIFY

- 专家建议记录重开时间与第二局路线；V0.5 先建立人工盲测表，不接入持久化或上传分析系统。
- 美术专家建议用柔和未知共鸣提示替代直接路线提示；为避免同样的测量污染，本轮完全移除下局暗示。
- Renderer 首帧继续依靠现有集中式 reset 回归，不新增脆弱的像素截图测试。

## REJECT

- 不采用数值专家的“首次升级 XP 70→90”：源码实际首次阈值是 60，70 是第二级阈值；建议识别错了活动参数。
- 不将 60 直接改为 90：单次 22.93 秒浏览器数据和优化机器人路线不足以支持大幅改变前期节奏。
- 不增加更亮 XP、同步闪烁、额外粒子、全屏辉光或新美术资产。
- 不做空间网格、对象池、循环状态机或其他宽泛工程重构。

## LATER

- 12～20 名首次玩家盲测；至少先完成 5 人可用性小样本。
- 记录首次升级时间、是否能复述元素反应、是否自发重开、决定重开耗时、重开者是否主动换路线。
- 如果真人分布显示首次升级持续过早，再用配置副本做 60/70/90 单变量对比。
- 自动路线仍未验证死亡公平、压力、爽感和“一局再来”。

## V0.5 成功标准

- 首次升级显示一次路线规则；后续升级不重复显示。
- Wind、Ice、第三项卡片分别正确解释路线影响，且不改变升级池逻辑。
- 结算只陈述本局路线与反应数据，不出现下局建议。
- 致死反应无重复死亡、击杀、XP、掉落或里程碑。
- 50 次循环压力后无第二 RAF、旧 run 推进或输入残留。
- 全量单元/集成、E2E、两条路线仿真和真实 Chromium 试玩重新通过。
- 不把自动化通过描述为“已经好玩”或“玩家已经理解”。
