# V0.8 双代理评审与验收

日期：2026-08-08
版本：V0.8 Long-run Performance + Hybrid Visual Language
Git 基线：`5de985f7842541c71fc5f033a7511246bdff4f44`

## 本轮目标

- 解决无尽模式长时间运行后逐渐卡顿的问题。
- 采用混合美术方向：65% Minimal Premium、25% Neon Elemental、10% Arcane Fantasy。
- 保持玩家、危险、技能与 XP 在高压战场中的优先级清晰。
- 用 10 分钟真实墙钟自动试玩验证，而不是只看短时平均 FPS。

## 双代理分工

- Codex：实现、测试、浏览器实机验收、性能证据、集成与最终决策。
- 独立工程审查代理：空间网格、碰撞候选、对象生命周期、长时转向与测试隔离。
- 独立视觉审查代理：玩家身份、敌人轮廓、XP 层级、反应辨识度、辉光与震屏预算。

## 关键问题与处理

### ACCEPT

- 采用可复用空间网格和查询缓冲区，覆盖最近目标、投射物命中、冰川、霜冻、点燃、热冲击和火焰龙卷。
- 加入滚动帧时间统计、实体峰值、碰撞候选/精确检查和 HUD 写入计数。
- HUD 改为脏分组更新；时间降为 1 Hz，生命、等级、XP、爆发和武器只在变化时写入。
- XP、玩家、敌人和元素反应使用不同形状与有限辉光；精英保留金色识别层。
- 自动试玩转向加入墙体、玩家与敌人半径，消除等距目标的数组顺序依赖。

### MODIFY

- 初版 Vacuum Blade 在逐个移动敌人后重建整个网格，改为单实体增量 `update()`。
- 初版 XP 教程签名含浮点距离，造成 HUD 高频写入；改为仅记录“是否应显示”。
- 初版死亡震屏过强；普通击杀取消震屏，受伤与元素反应分别限制为 3、3、2.5。
- 初版自动试玩会在约 500 秒死亡；增加仅 `?test=1` 暴露的 sustain 测试入口，正式 URL 明确不暴露。

### REJECT

- 不以全局高 Bloom、每次击杀强震屏或无限粒子掩盖反馈不足。
- 不为本轮引入大规模引擎重写或全量对象池。
- 不使用自动回血改变正式玩法；sustain 只属于测试路由。

### LATER

- 进一步处理空间网格 `update()` 对旧坐标/半径准确性的调用约束。
- 自动试玩加入敌人速度预测和更长的 20～30 分钟样本。
- Boss 独立视觉资产与正式序列帧，待核心无尽循环的人类试玩稳定后推进。

## 版本十问

1. 游戏现在好玩吗？——核心打怪、吸收、升级与反应循环成立；长期内容深度仍需人类连续试玩。
2. 前 30 秒是否有反馈？——有，首次升级中位数约 22 秒，命中、击杀、XP 与投射物均有分层反馈。
3. 第一次升级是否足够快？——是，落在 30 秒目标内。
4. 第一次明显能力质变何时出现？——元素反应条件满足后出现；具体分布需继续采集人类试玩数据。
5. 当前最强 Build 是什么？——自动样本能形成 Fire Tornado 与 Thermal Shock，但尚不足以断言唯一最强。
6. 有无垃圾升级？——未发现自动测试中完全无效的选项；主观价值仍需玩家选择数据。
7. 死亡是否公平？——自动转向可稳定规避，但人类高压死亡原因仍要继续观察。
8. Boss 是否只是血厚？——当前无尽版还未完成正式 Boss，属于后续内容缺口。
9. 画面是否看得懂？——桌面与移动端均通过本轮浏览器审查；高压峰值仍保持玩家优先。
10. 失败后是否想再来一局？——Build 差异已提供动机，但排行与终局变化仍需后续增强。

## 结论

V0.8 相比上一版在长时稳定性、战场可读性和视觉身份上有可测量改进，可以发布。下一轮不应继续堆叠粒子，而应优先验证 20～30 分钟内容节奏、Boss/阶段事件和 Build 差异。
