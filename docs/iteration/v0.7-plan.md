# Elemental Survivor V0.7：无尽进化实施计划

## 目标

把当前可玩的 Demo 推进为具有长期决策价值的无尽模式：基础武器全部可获得，满配后经验仍持续产生有效选择；玩家可主动释放元素爆发；死亡后用本地榜单与战斗复盘驱动下一局；同时重做主角、敌人和能量粒子的视觉层级。

本轮保持 Canvas 2D、原生 JavaScript 和现有单页面架构。所有改动仅保存在本地分支，不提交、不推送、不部署。

## 双代理结论

ChatGPT Plus 专家建议采用“进化层”而不是无限小数值升级：约 70% 玩家选择、20% 半随机候选、10% 世界事件。Codex 接受这一方向，但暂不增加硬武器槽上限；当前只有三种基础武器，Build 差异先由每把武器三选一的互斥变异、最多两条融合路线和无尽精通代价形成。

视觉方向采用：Minimal Premium 55% + Neon Elemental 35% + Arcane 10%。战场信息优先级固定为玩家 > 精英/Boss > 普通敌人 > 技能 > 经验粒子。

## 可验收标准

- 三种基础武器均可解锁；每把武器最多选择一个互斥行为变异。
- 最多同时持有两条元素融合；第三条融合不会进入候选池。
- 一次性升级耗尽后，升级池仍稳定给出三个可重复的无尽精通选择，经验不会失效。
- 元素爆发通过击杀与吸收能量充能；满能量后可用 `Space` / `E` 或手机按钮主动释放。
- 爆发持续 6 秒，强化机动、攻击节奏和吸取范围，制造战术窗口而不是全屏清场。
- 无尽 Director 在不同时间段切换世界规则、生成精英，并保持压力/释放波形和实体上限。
- 游戏结束时记录本机生存时长榜单，并展示 Build、变异、融合、最高伤害来源、死因和下一局建议。
- 主角拥有稳定水晶核心与已装备元素印记；怪物以暗色轮廓区分行为，精英使用金色边缘。
- 能量粒子至少有普通、稀有、精英三档造型与价值，吸附轨迹为弧线，并在上限时合并而不丢失经验。
- `npm test`、`npm run check`、关键 E2E 和真实 Edge 浏览器试玩均通过。

## 执行顺序

1. 用模型测试锁定双融合槽、互斥变异与可重复精通。
2. 用模拟和输入测试锁定爆发充能、释放、持续效果及手机/键盘入口。
3. 扩展 Director 的世界规则和精英生成，补齐纯逻辑测试。
4. 增加本地榜单与死亡复盘，覆盖排序、容量、坏数据恢复和重复写入。
5. 在不改变碰撞轮廓的前提下重做程序化玩家、怪物、能量粒子和 HUD。
6. 更新 E2E，运行平衡模拟与真实浏览器试玩；发现缺陷时先补回归测试再修复。
7. 将 Plus 建议、Codex 取舍、试玩证据和剩余风险写入 `v0.7-review.md`。

## 刻意延后

- 在线排行榜、账号、后端、每日任务和永久数值碾压。
- 大量新武器、新地图、新角色和复杂剧情。
- 依赖外部图片的大规模资产替换；本轮先确保程序化美术形成统一语言且手机性能稳定。
