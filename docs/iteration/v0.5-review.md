# V0.5 验收与迭代结论

日期：2026-08-01  
状态：工程验收通过；冰路线平衡门槛未通过  
Git：当前目录不是 Git 仓库；全部改动 Local only

## 本轮范围

V0.5 没有增加敌人、武器、反应、地图或 Meta 内容。它只验证两件事：玩家能否在投入 Build 前看到单反应槽规则，以及一局结束后能否复盘本局路线。

已实现：

- 首次升级一次性显示“本局只能激活一种反应，首个完成的反应锁定路线”。
- Wind / Ice 卡片预告对应配方；第三项明确为即时强化且不锁路线。
- 结算显示本局路线、反应激活数与命中数，不再建议下一局选择什么。
- Thermal Shock 同一步多次火焰命中造成致死时，死亡、击杀、XP、掉落和里程碑各结算一次。
- 50 次 GameLoop 启停和 50 次 run 重启覆盖重复 RAF 与状态残留。
- 浏览器自动试玩控制器补充边界脱困与危险分级拾取测试；它只用于测试，不进入生产代码。

## 结论与下一轮优先级

### ACCEPT

- 单反应槽继续作为可测的核心约束，而不是立即扩成多反应系统。
- 路线规则只在首次升级出现，避免后续弹窗重复堆信息。
- 中性结算保留玩家自主决定下一局路线。
- 工程边界与生产测试 API 隔离达到本轮要求。

### MODIFY

- V0.4 对两条路线“都能形成反应”的验证不等于“路线强度相当”。V0.5 的三分钟分路线证据将下一轮问题改写为：在不削弱 Wind 爽点的前提下，使 Ice 的生存和清场能力达到可接受区间。
- 浏览器自动试玩只是可重复压力样本；下一轮仍需真人判断死亡公平性与重玩冲动。

### REJECT

- 不把 75/75 与 E2E 2/2 表述成“游戏已经好玩”。
- 不因单次 Wind FPS 偏低而降低 FPS >45 的目标或给渲染代码做无证据重构。
- 不在 V0.5 收口时临时改 XP、敌人、Director 或全局伤害以掩盖 Ice 路线差异。

### LATER

- 5 人可用性小样本与 12～20 人正式盲测。
- Boss、更多元素反应、Meta、成就与设置页。
- 当核心路线接近后，再讨论更强 VFX 和正式美术资产。

## 版本十问

1. **现在好玩吗？** 自动化证明循环可持续并有成长，但不能证明主观好玩；需要真人盲测。
2. **前 30 秒有反馈吗？** 有。30 种子平均首次击杀 1.54 秒、首次 XP 3.60 秒、首次升级 23.13 秒。
3. **第一次升级足够快吗？** 逻辑模拟中位数 22.09 秒，落在目标前沿；浏览器样本有 22～54 秒波动，需要真人分布确认。
4. **第一次明显质变何时出现？** 第二次路线升级可形成反应，但当前没有精确记录首次反应解锁/命中的时间，需要补遥测。
5. **当前最强 Build 是什么？** 现有证据指向 Fire + Wind：180 秒 30/30 存活；Fire + Ice 仅 18/30。
6. **有垃圾 Upgrade 吗？** 暂无足够证据判定单卡为垃圾；Ice 路线整体偏弱，不能直接归因某一张卡。
7. **死亡公平吗？** 结算能指出最后伤害来源；Ice 浏览器局死于重装怪接触，但死亡瞬间可读性仍需真人验证。
8. **Boss 只是血厚吗？** V0.5 尚未实现 Boss，不能回答。
9. **画面能看懂吗？** 截图中玩家、敌人、XP、攻击与结算信息可区分；高压即时可读性仍需人工观察。
10. **失败后想再来一局吗？** 自动化无法回答；必须继续测试。

## Remaining Risks

- Ice 路线三分钟存活率只有 60%，是下一轮 P0。
- 首次反应解锁与首次反应命中时间尚无独立里程碑。
- 尚无真人理解率、死亡公平性和自发重开数据。
- 当前目录没有 Git 基线，无法提供 commit 级差异或回滚点。
