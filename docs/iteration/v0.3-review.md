## ACCEPT

- 修复致死 Fireball 先把目标打到零血、随后霜爆因跳过该目标而漏算的语义问题；触发目标必须能获得一次反应命中。
- 第一轮三选一固定包含 Wind Blade、Ice Shard 和一个随机第三项，让 Build 分叉成为明确选择。
- 一局只允许锁定一个元素反应；首个反应形成后，另一路反应从升级池退出。
- 当路线条件首次满足时，下一次升级保证出现对应反应，避免随机池掩盖路线验证。
- 重开时清空 Renderer 的震屏、闪光、受伤提示和爆发残留，并补回归测试。
- XP 首次拾取提示改为“靠近 ◇ 收集元素能量”；远处 XP 降低亮度，近处才发光。
- 反应说明使用明确配方：`火 + 风 → 火焰龙卷｜持续环绕`、`火 + 冰 → 霜爆｜减速后引爆`。

## MODIFY

- 数值专家建议在语义修复后视情况把霜爆半径 72 调到 84；Codex 先保持 72，用独立路线仿真验证可靠性，不同时改语义与强度。
- 玩家体验专家建议结算页给下一局方向；实现为一句“首轮选择另一条元素路线”，不加入复杂 Build 推荐或元进度。
- 工程专家建议补 App 边界测试；现有 E2E 已覆盖暂停、恢复、死亡、重开，并增加仅 `?test=1` 可见的确定性 `defeat()` 测试钩子，正式 URL 不暴露它。

## REJECT

- 不同时开放两种反应；这会继续让自动路线收齐所有 Build，无法验证选择意义。
- 不提高霜爆伤害或半径；修正后 Wind/Ice 两条路线的命中与伤害占比已达到预设门槛。
- 不调整 XP、敌人压力或生命；自动避敌路线满血只能证明测试控制器强，不能证明真人觉得太容易。
- 不加入 Boss、Elite、新元素、新地图、元进度或更多视觉特效。

## LATER

- 真人首次玩家对两条路线的理解、偏好、死亡公平与“再来一局”意愿。
- 若人类玩家仍无法识别 XP，再评估短时指引动画；当前不添加粒子或全局泛光。
- 高压实体达到性能门槛后，再考虑空间网格、对象池和 HUD 更新优化。
